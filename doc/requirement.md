# AI 小说问答助手需求文档

## 1. 项目背景

本项目是一个简单的 AI 小说问答助手。用户提供一本小说原文后，可以在控制台输入问题，系统根据小说原文检索相关内容，并让大语言模型基于检索到的原文片段进行回答。

项目当前处于 MVP 阶段，目标不是一次性做成完整产品，而是先验证最核心链路：小说导入、文本切片、向量化、问题召回、基于原文回答。

## 2. 核心目标

项目的核心目标是实现一个“基于小说原文的问答助手”：

- 用户可以围绕小说人物、情节、事件、关系等内容提问。
- 系统回答必须来自小说原文提供的证据。
- 当小说原文中没有足够依据时，系统应明确说明无法从原文确认，而不是让 LLM 自由猜测。
- 用户可以查看系统召回的原文片段，便于判断回答是否可靠。

## 3. 核心特色

本项目最重要的特色是：所有回答必须基于小说原文。

普通 LLM 容易根据通用知识或语言模式生成看似合理但未必真实的答案。对于小说问答场景，这会带来明显问题：

- 编造不存在的情节。
- 混淆人物关系。
- 将其他作品或常见套路套用到当前小说。
- 对原文没有明确描述的内容进行过度推断。

因此，本项目采用 RAG 技术，将小说原文作为唯一可信知识来源。LLM 只负责根据召回的原文片段组织语言，不负责凭空补充事实。

## 4. 用户场景

### 4.1 查询剧情细节

用户想知道某个事件是否发生过、如何发生、相关人物是谁。系统应召回相关原文并给出简明回答。

示例问题：

- 主角第一次遇到某个人是在什么时候？
- 某个事件的起因是什么？
- 某个地点发生过哪些重要情节？

### 4.2 查询人物关系

用户想确认人物之间的关系、冲突、身份或态度变化。系统应基于小说中明确出现的描述进行回答。

示例问题：

- A 和 B 是什么关系？
- A 为什么不信任 B？
- 某个人的真实身份有没有被揭示？

### 4.3 查看原文依据

用户不只需要答案，还需要知道答案来自哪些原文片段。MVP 阶段应支持展示召回片段，方便人工检查 RAG 效果。

### 4.4 调试召回效果

开发者需要在不调用 LLM 的情况下，只查看问题对应的召回结果，用来判断切片、向量化和相似度检索是否有效。

## 5. MVP 范围

MVP 阶段只实现最小可用能力：

- 支持导入一本本地小说文本。
- 支持将小说按固定长度切片。
- 支持调用外部 embedding API 生成向量。
- 支持将切片和向量保存到本地文件。
- 支持控制台输入问题。
- 支持根据用户问题召回相关原文片段。
- 支持将召回片段拼接给 LLM 生成回答。
- 支持展示回答引用的原文片段。
- 支持仅查看召回结果，不调用 LLM。

## 6. 非目标范围

以下能力不进入 MVP 阶段：

- Web 前端或桌面客户端。
- 多用户系统。
- 多小说书库管理。
- 登录、权限、收藏、历史记录等产品功能。
- 复杂的章节识别、目录解析、语义切片。
- 正式向量数据库。
- 知识图谱。
- 自动化问答评测系统。
- 多模型路由。
- 长期记忆或用户画像。
- 在线爬取小说。

这些能力可以在后续版本中逐步扩展。

## 7. 基本流程

### 7.1 建索引流程

1. 开发者准备一本纯文本小说。
2. 系统读取小说文本。
3. 系统按固定参数切分文本。
4. 系统调用 embedding API 为每个 chunk 生成向量。
5. 系统将 chunk 文本、元数据和向量保存到本地索引文件。

### 7.2 问答流程

1. 用户在控制台输入问题。
2. 系统调用 embedding API 将问题转换为向量。
3. 系统在本地索引中计算问题向量和 chunk 向量的相似度。
4. 系统取相似度最高的若干个 chunk 作为上下文。
5. 系统将问题和上下文拼接成 prompt。
6. LLM 根据上下文生成回答。
7. 系统输出答案和引用片段。

### 7.3 召回查看流程

1. 用户在控制台输入问题。
2. 系统只执行向量召回。
3. 系统输出 top_k 召回片段和相似度分数。
4. 系统不调用 LLM。

## 8. 回答原则

系统回答必须遵守以下原则：

- 只基于召回到的小说原文片段回答。
- 不使用 LLM 的通用知识补全小说事实。
- 不编造人物、地点、事件或关系。
- 如果上下文不足，应明确说明“原文中没有足够信息确认”。
- 如果答案来自多个片段，应尽量合并信息，并保留引用来源。
- 回答应简洁清楚，避免无依据的长篇推测。

## 9. 成功标准

MVP 被认为可用，需要满足以下标准：

- 能成功读取一本小说纯文本文件。
- 能按 `chunk_size = 1000`、`overlap = 200` 切分文本。
- 能为每个 chunk 生成向量并保存本地索引。
- 用户输入小说相关问题时，系统能召回相关原文片段。
- 系统能基于召回片段生成回答。
- 回答中能看到对应的引用片段。
- 对于原文中没有依据的问题，系统不会编造答案。
- 开发者可以单独查看召回结果，调试 RAG 效果。

## 10. 后续优化方向

MVP 验证通过后，可以考虑以下优化：

- 支持多本小说。
- 引入向量数据库。
- 增加章节识别和章节级引用。
- 优化 chunk 切分策略。
- 增加 rerank 阶段，提高召回质量。
- 增加 Web 前端。
- 增加问答历史。
- 增加回答质量评测。
- 增加不同模型配置。
- 支持更多文档格式，例如 EPUB、PDF、DOCX。
